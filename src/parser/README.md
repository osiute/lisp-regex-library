# Архитектура модуля и пояснение алгоритма парсинга

## Составные файлы
Модуль парсинга предназначен для синтаксического анализа строки регулярного выражения и преобразования её в объект абстрактного дерева (AST). Модуль разделён на 5 логических файлов:
- **state.lisp** — реализует функционал посимвольного сканера строки регулярного выражения. Описывает структуру `parser-state`, содержащую входную строку и индекс указателя, а также базовые действия указателя;
- **char-class.lisp** — отвечает за синтаксический анализ символьных классов и спецпоследовательностей. Разбирает диапазоны в квадратных скобках вида `[a-z0-9]` и `[^abc]` с поддержкой отрицания, а также экранированные классы `\d`, `\w` и `\s`, приводя их к единому виду диапазонов символов в `ast-char-class`;
- **range-quantifier.lisp** — выделенный подмодуль разбора фигурных скобок квантификации вида `{n}`, `{n,m}`, `{n,}` и `{,m}`. Проверяет корректность границ диапазонов, отсутствие символьных мусорных значений и валидирует условие $min \le max$;
- **grammar.lisp** — ядро рекурсивного спуска, реализующее правила грамматики в соответствии с приоритетом операторов (`parse-expression`, `parse-concatenation`, `parse-quantifier`, `parse-atom`). Преобразует последовательность элементов в дерево `ast-node`;
- **main.lisp** — точка входа в подсистему парсинга. Предоставляет публичную функцию `parse-regex`, которая инициализирует `parser-state`, запускает разбор верхнего уровня и проверяет полное вычитывание входной строки.

## Алгоритм рекурсивного спуска
* **LL(1):** Сканирование выполняется слева направо, а для принятия решения о выборе ветви грамматики используется предпросмотр ровно на **1 символ вперед** (`parser-peek`).
* **Нисходящий анализ (Top-Down):** Построение AST начинается с верхнеуровневых операций (альтернация) — `parse-expression`, и рекурсивно спускается к неделимым атомам (литералам и символьным классам) — `parse-atom`. 

## Описание уровней разбора
1. **parse-atom**
  * Якоря `^` и `$` → `ast-anchor` (`:start-of-line` / `:end-of-line`).
  * Скобки `(...)` → рекурсивный вызов `parse-expression` и проверка закрывающей `)`.
  * Скобки `[...]` → вызов `parse-bracket-char-class`.
  * Спецсимволы `\` → вызов `parse-escape-char-class`.
  * Точка `.` → `ast-char-class` со всеми символами.
  * Обычные символы → `ast-literal`.

2. **parse-quantifier**
  * Вызывает `parse-atom`.
  * Проверяет следующий символ:
    * `*` → `make-ast-star`
    * `+` → `make-ast-plus`
    * `?` → `make-ast-question`
    * `{` → вызов `parse-range-quantifier` и сборка `make-ast-range`
  * Запрещает навешивать квантификаторы на якоря `^` и `$`.

3. **parse-concatenation**
  * В цикле вызывает `parse-quantifier`, пока не встретит `|`, `)` или конец строки.
  * Собирает полученные узлы в `make-ast-concat`, либо возвращает nil (собрано 0 узлов) или единственный узел.

4. **parse-expression**
  * Вызывает `parse-concatenation` для левой ветви.
  * При наличии `|` рекурсивно собирает правую ветвь в `make-ast-alt`.
