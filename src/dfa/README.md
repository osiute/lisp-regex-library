# Архитектура модуля dfa и алгоритмы ленивой детерминизации

## Составные файлы
Модуль детерминированных конечных автоматов (DFA) предназначен для ленивой детерминизации недетерминированного конечного автомата (NFA) методом подмножеств (subset construction), выполнения контекстно-зависимых переходов, динамического построения и кэширования состояний ДКА, а также автоматического управления памятью. Модуль разделён на 6 логических файлов:
* **dfa.lisp** — Определяет ключевые типы данных: `dfa-state` (содержит каноническое подмножество состояний НКА `nfa-set`, флаг принимающего состояния `accept-p` и хэш-таблицу переходов `transitions`) и `dfa` (хранит реестр уникальности `state-map`, вектор сгенерированных состояний `states`, вектор стартовых состояний по контекстам `start-states`, ограничение `max-states` и предварительно выделенные буферы `nfa-buffer-queue` и `nfa-buffer-visited`). Предоставляет функции `allocate-nfa-buffers` и `make-dfa-instance`;
* **state-registry.lisp** — Изолирует логику идентификации и хранения уникальных состояний ДКА. Предикат `nfa-set-accept-p` проверяет наличие принимающего состояния НКА в подмножестве, `create-dfa-state` конструирует узел ДКА, а `register-dfa-state!` заносит его в вектор и хэш-таблицу отображения. Функция `get-or-register-dfa-state!` обеспечивает дедупликацию и получение ID состояния;
* **start-states.lisp** — Управляет фиксированным вектором `start-states` (128 элементов) для различных масок контекста как привязанного (anchored), так и непривязанного (unanchored) автомата. Функция `compute-start-nfa-closure` строит начальное epsilon-замыкание для стартового состояния НКА с учётом предиката `unachored-p` (в дальнейшем будет использоваться для нахождения границ подстрок, соответствующих паттерну регулярного выражения), а также начального контекста без лишних аллокаций. Функция `get-dfa-start-state!` отвечает за кэширование и выдачу ID стартового состояния ДКА;
* **step.lisp** — Реализует функцию перехода по графу `dfa-step`. Функция `pack-transition-key` упаковывает пару (`class-id`, `context`) в один `fixnum`-ключ. Быстрый путь (`hot-path`) извлекает результат из хэш-таблицы за $O(1)$. При отсутствии перехода срабатывает «холодный путь» (`cold-path`), вычисляющий целевое подмножество НКА через `compute-target-nfa-set` и строящий epsilon-замыкание. При заполнении кэша `cold-path-no-dfa-state` вызывает сброс памяти через `ensure-cache-space!`;
* **cache.lisp** — Обеспечивает контроль объёма задействованной памяти. Предикат `dfa-cache-full-p` проверяет достижение лимита `max-states`. Функция `flush-dfa-cache!` производит очистку таблицы `state-map`, обнуление вектора `states` и сброс вектора `start-states` значениями `-1`. Функция `ensure-cache-space!` выполняет условный сброс кэша;
* **main.lisp** — Выступает публичным API модуля DFA: предоставляет функцию создания ленивого автомата `make-lazy-dfa` (с валидацией `max-states` $\ge 2$), вычисление стартового состояния `dfa-get-start-state`, выполнение перехода `dfa-step-state`, считывание флага завершения `dfa-accept-state-p`, инспекцию размера кэша `dfa-cache-count` и принудительный сброс `reset-dfa!`.

## Ключевые алгоритмы и принципы работы
* **Ленивая детерминизация (Lazy Subset Construction):**
    * **Компоновка «по требованию»:** Состояния ДКА и ребра переходов между ними не генерируются заранее, а вычисляются динамически во время сканирования входной строки только для фактически встречающихся путей.
    * **Идентификация через каноническое подмножество:** Каждое состояние ДКА однозначно определяется отсортированным вектором уникальных состояний НКА (`nfa-set`). Хэш-таблица `state-map` сопоставляет `nfa-set` со сгенерированным целым ID состояния.
* **Упаковка ключей переходов и Fast Path:**
    * **Битовая упаковка (`pack-transition-key`):** Параметры перехода (`class-id`, `context`) упаковываются в один `fixnum` с помощью сдвига `(ash class-id 6)` и побитового `logior` с 6-битной маской контекста.
    * **Hot Path ($O(1)$):** Хэш-таблица `transitions` внутри каждого `dfa-state` кэширует переходы по упакованному ключу. Повторный шаг по той же паре символа и контекста выполняется за замеряемое фиксированное время $O(1)$ без обращения к НКА.
    * **Cold Path:** При первом переходе рассчитывается смещение по `class-id` (`compute-nfa-class-id-transitions`), строится эпсилон-замыкание (`compute-nfa-closure`) и регистрируется новое состояние.
* **Управление памятью и сброс кэша (Cache Flush):**
    * **Ограничение `max-states`:** Количество закэшированных состояний подчинёно строгому лимиту `max-states`.
    * **Инвалидация и сброс (`flush-dfa-cache!`):** При превышении лимита происходит сброс реестра `state-map`, обнуление вектора `states` и сброс `start-states`. Это гарантирует предсказуемый расход памяти во время работы алгоритма.

## Описание процесса обработки и выполнения шага
1. **Инициализация стартового состояния (`start-states.lisp`)**
* `get-dfa-start-state!` проверяет индекс контекста для автомата определённого типа (anchored или unanchored) в векторе `start-states` (размером 128 элементов).
* 0-5 разряды в двоичном представлении индексы означают маску контекста, 6 разряд означает тип автомата: 0 — anchored, 1 — unanchored.
* Если состояние с данным контекстом не вычислено (`-1`), вычисляется `compute-start-nfa-closure` от начального состояния НКА с учётом начальной битовой маски `context`.
* Результат сохраняется в реестре `state-registry` и заносится в `start-states`.
2. **Выполнение шага перехода (`step.lisp`)**
* `dfa-step` считывает текущий объект `dfa-state` по его ID и формирует упакованный ключ `key` через `pack-transition-key`.
* Проверяется наличие `key` в таблице `transitions` текущего состояния:
* **Hot Path:** Если ключ найден, возвращается закэшированный `target-state-id`.
* **Cold Path:** Если ключ отсутствует, вызывается `compute-target-nfa-set`.
* `compute-target-nfa-set` вычисляет прямые переходы НКА по `class-id`, а затем передаёт их в `compute-nfa-closure` с учётом текущего контекста. Для состояния, включающего `unanchored-start-state` НКА, `compute-target-nfa-set` всегда будет включать его же в результирующее множество (т.к. оно содержит петлю в себя же с `label` `:any-class-id`).
* Если полученное подмножество пустое, в `transitions` записывается `-1` (тупиковое состояние).
* В противном случае `get-or-register-dfa-state!` проверяет наличие такого подмножества в `state-map`. При его отсутствии создаётся и регистрируется новый `dfa-state`, а перед занесением при необходимости вызывается `ensure-cache-space!`.
