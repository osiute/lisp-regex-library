# Архитектура модуля nfa и алгоритмы построения и обхода НКА

## Составные файлы
Модуль недетерминированных конечных автоматов (NFA) предназначен для трансляции абстрактного синтаксического дерева (AST) в НКА по алгоритму Томпсона, вычисления контекстно-зависимых epsilon-замыканий, инверсии графа и визуализации. Модуль разделён на 7 логических файлов:
- **nfa.lisp** — Определяет ключевые типы данных: `nfa-edge` (содержит метку перехода `label` и целевое состояние `target`) и `nfa` (содержит вектор списков исходящих переходов `states`, стартовое и принимающее состояния);
- **nfa-builder.lisp** — Описывает структуру `nfa-builder` (содержит вектор состояний `states-vector`). Предоставляет функции добавления состояний (`builder-add-state!`), прокладки рёбер (`builder-add-edge!`), валидации конфликтов переходов по классам эквивалентности (`check-or-add-class-edge!`) и сборки итогового неизменяемого автомата (`finalize-nfa`);
- **ast-to-nfa.lisp** — Определяет вспомогательную структуру `nfa-fragment` для хранения границ подграфов. Реализует трансляцию узлов AST в NFA-фрагменты и набор состояний по алгоритму Томпсона (`compile-ast-node`): обработку пустого выражения, литералов, символьных классов, контекстных якорей, конкатенации, альтернации, квантификаторов (`*`, `+`, `?`, `{m,n}`) и сшивание фрагментов epsilon-переходами (`join-fragments!`);
- **closure.lisp** — Реализует алгоритм поиска в ширину (BFS) `epsilon-closure` с использованием плоского буфера очереди `queue` и битового вектора `visited` для предотвращения повторных посещений. Предикат `nfa-edge-traversable-p` проверяет проходимость рёбер с учётом битовой маски текущего контекста `context` (границы слова, начало/конец строки). Функция `finalize-closure-array` извлекает отсортированный статический вектор состояний;
- **reverse-nfa.lisp** — Содержит вспомогательные функции для разворота направления рёбер НКА: `make-raw-reversed-nfa` меняет местами `start-state` и `accept-state`, а функции `add-reversed-edge!` и `reverse-state-edges!` транспонируют списки смежности для построения обратного автомата двухпроходного поиска;
- **nfa-visualizer.lisp** — Предоставляет инструментарий генерации DOT-кода (`nfa-to-dot`) для отладки и визуального анализа структуры автомата. Выполняет форматирование спецсимволов и меток рёбер (`format-nfa-edge-label`), а также генерацию описаний узлов и переходов (`write-dot-node`, `write-dot-edges`).
- **main.lisp** — Выступает в роли API модуля NFA для внешнего взаимодействия с модулем детерминизации (`dfa`). Предоставляет функции `build-nfa-from-ast`, `compute-nfa-closure` (с автоматическим выделением рабочих буферов `queue` и `visited` под размер NFA) и `reverse-nfa`.

## Ключевые алгоритмы и принципы работы

* **Конструкция Томпсона:**
  * **Компоновка из подграфов:** Каждый узел AST транслируется в `nfa-fragment` с ровно **одним входом** и **одним выходом**.
  * **Изоляция и сшивка:** Сложные составные конструкции (альтернация, квантификаторы, конкатенация) строятся за счёт выделения новых внешних состояний и объединения фрагментов epsilon-переходами за `O(1)`.
* **Контекстные epsilon-переходы и epsilon-замыкание:**
  * **Обход в ширину (BFS):** Для сбора замыкания используются заранее выделенная плоская очередь `queue` и битовый вектор посещений `visited`, исключающий повторный обход узлов (гарантирует сложность `O(V + E)`).
  * **Динамическая фильтрация рёбер:** Контекстные якоря (`^`, `$`, `\b` и др.) кодируются как специальные метки рёбер. При вычислении замыкания предикат `nfa-edge-traversable-p` проверяет бит соответствия в маске `context` через `logbitp`.
  * **Канонизация результата:** Выходной вектор состояний сортируется по возрастанию индексов, что делает результат каноническим представлением состояния будущей детерминированной машины (DFA).
* **Инверсия графа НКА:**
  * Транспонирование графа выполняет инверсию связей за один линейный проход по массиву состояний `O(V + E)`, инвертируя направление вызовом `add-reversed-edge!`.

## Описание процесса компиляции и обработки

1. **Компиляция AST в НКА (`ast-to-nfa.lisp`)**
  * `compile-ast-empty` / `compile-ast-literal` / `compile-ast-anchor` → базовые 2-состояния фрагменты.
  * `compile-ast-char-class` → параллельные рёбра для каждого `class-id` с проверкой дедупликации через `check-or-add-class-edge!`.
  * `compile-ast-concat` → последовательное соединение элементов через `join-fragments!`.
  * `compile-ast-alt` → ветвление из нового `s` в верхнюю и нижнюю ветви и сведение выходов в новый `a`.
  * `compile-ast-star` / `compile-ast-plus` / `compile-ast-question` / `compile-ast-range` → петли и обходные epsilon-пути.

2. **Вычисление эпсилон-замыкания (`closure.lisp`)**
  * `init-closure-queue!` → сбрасывает `visited`, обнуляет `fill-pointer` у `queue` и помещает в очередь начальные состояния.
  * Цикл `loop while (< head (length queue))` → извлекает текущее состояние и обрабатывает исходящие рёбра.
  * `nfa-edge-traversable-p` → проверяет, является ли ребро `:epsilon` или совпадает ли класс якоря с флагами битовой маски `context`.
  * `finalize-closure-array` → копирует элементы очереди в статический `simple-array fixnum` и выполняет сортировку `sort`.
