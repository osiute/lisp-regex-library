# Модуль engine

Конечный модуль, содержащий экспортируемые функции библиотеки.

## Терминология

- **Межсимвольная позиция** — точка раздела между символами строки `text` (от `0` до `N` включительно для строки длины `N`). Для строки `"abc"` позиции имеют вид: `0 'a' 1 'b' 2 'c' 3`. Для пустой строки `""` существует единственная позиция `0`. Дальше по тексту межсимвольная позиция будет называться просто **позицией**.
- **Вхождение** — подстрока исходной строки (в библиотеке исходная строка называется `text`), которая соответствует регулярному выражению. Диапазоны вхождения имеют вид $\left[\text{начальный индекс символа в строке}, \text{конечный индекс символа в строке}\right)$ или $\left[\text{позиция начала}, \text{позиция конца}\right]$, т.к. *в строке из $N$ символов существует $N + 1$ позиций*.
- **Прямой проход** — обработка межсимвольных позиций строки `text` на заданном интервале `[left-bound-pos, right-bound-pos]` **слева направо** в поисках **принимающей (терминальной) позиции**, т.е. такой позиции, при достижения которой **прямой ДКА** оказался в терминальном состоянии. В качестве результата возвращаются индекс позиции *(не индекс символа в `text`, а именно позиции)* и `last-state-id` — ID состояния, в котором оказался ДКА.
- **Обратный проход** — обработка межсимвольных позиций строки `text` на заданном интервале `[left-bound-pos, right-bound-pos]` **справа налево** в поисках **принимающей (терминальной) позиции**, т.е. такой позиции, при достижения которой **обратный ДКА** оказался в терминальном состоянии. В качестве результата возвращаются индекс позиции *(не индекс символа в `text`, а именно позиции)* и `last-state-id` — ID состояния, в котором оказался ДКА.
- **Жадный проход** — проход, цель которого — поиск наиболее поздней позиции относительно старта. Для прямого прохода ищется самая правая позиция, на которой ДКА был в терминальном состоянии; для обратного — самая левая.
- **Ленивый проход** — проход, цель которого — поиск наиболее ранней позиции относительно старта. Для прямого прохода ищется самая левая позиция, на которой ДКА впервые перешёл в терминальное состояние; для обратного — самая правая.
- **Вычисление ветки** — поиск относительно начальной позиции $i$ такой конечной позиции $j$, что ДКА переходит в терминальное состояние. Проще говоря, это определение конца $j$ **вхождения** $(i \cdot j)$, где $j$ заранее неизвестен. Для обратного прохода происходит поиск неизвестного $i$ относительно известного $j$.
- **Привязанный проход** — проход, при старте которого ДКА *не находится* в **непривязанном состоянии** (множество состояний НКА не содержит `unanchored-start-state`). При переходе на каждую следующую позицию новые ветки вычислений не добавляются, а продолжают обрабатываться только ранее запущенные. *Можно ассоциировать с проходом, который **не** собирает новые ветки*.
- **Непривязанный проход** — проход, при старте которого ДКА содержит в своём множестве `unanchored-start-state`. На каждой позиции не только вычисляются существующие ветки, но и зародится новая ветка с началом в этой позиции (аналог добавления `.*` в начало выражения). *Можно ассоциировать с проходом, который собирает новые ветки*.

## Описание функционала и алгоритмов основных функций

- **`matches-p`** — проверяет строку на полное соответствие регулярному выражению. Использует прямой *привязанный жадный* проход на интервале `[left-bound-pos, right-bound-pos]`.
- **`contains-p`** — проверяет наличие хотя бы одного вхождения на интервале `[left-bound-pos, right-bound-pos]`. Использует прямой *непривязанный ленивый* проход.
- **`first-match-span`** — вычисляет границы `(START-MATCH . END-MATCH)` первого по семантике **Leftmost** вхождения в режимах **longest** или **shortest**. Использует цепочку проходов:
  1. **Прямой непривязанный ленивый проход** на `[left-bound-pos, right-bound-pos]`. Возвращает первую попавшуюся позицию конца `first-terminal-pos` и ID состояния `last-state-id`. Фактически определяет верхнюю границу для начала leftmost-вхождения. Если проход не зашёл в терминальное состояние, функция сразу возвращает `NIL`.
  2. **Прямой привязанный жадный проход** на `[first-terminal-pos, right-bound-pos]` с указанием стартового состояния `last-state-id` без `unanchored-start-state`. Возвращает `potential-rightest-end` (или `pre`). Определяет самую правую возможную границу конца для всех зародившихся веток.
  3. **Обратный непривязанный жадный проход** на `[first-terminal-pos, potential-rightest-end]` (справа налево). Засеивает реверсивный ДКА начальными состояниями для всех потенциальных концов и возвращает `last-state-id`.
  4. **Обратный привязанный жадный проход** на `[left-bound-pos, first-terminal-pos]` (справа налево) со стартовым состоянием из п.3 без `unanchored-start-state`. Возвращает самую левую позицию начала — `leftmost-start`.
  5. В зависимости от режима, на диапазоне `[leftmost-start, potential-rightest-end]` запускается **прямой привязанный проход**:
     - **longest** — *жадный* (`greedy-anchored-direct-pass`);
     - **shortest** — *ленивый* (`lazy-anchored-direct-pass`).
     Возвращает итоговую позицию конца `end-for-leftmost-occurence`.
- **`make-match-span-iterator`** — создаёт замыкание-генератор для последовательного вычисления всех совпадений на интервале.
- **`do-match-spans`** — макрос для итерации по совпадениям.
- **`all-match-spans`** — возвращает список точечных пар всех совпадений.
- **`replace-all`** — замена всех вхождений строки, соответствующих регулярному выражению на новую подстроку `replacement`. Возвращает новый объект строки.
- **`split`** — разбивает строку на подстроки, между которыми в исходной строке находятся вхождения. Возвращает список строк. Т.е. для `text` = "abc1def2ghi3" вернёт список ("abc" "def" "ghi" ""). Флаг `omit-empty-p` определяет, стоит ли включать пустые строки в возвращаемый список.

### Математическое доказательство корректности алгоритма поиска первого вхождения

Обозначим искомое **leftmost-longest** совпадение как пару межсимвольных позиций $(i_{LL}, j_{LL})$.

1. **Инвариант $i_{LL} \le \text{first-terminal-pos}$**
   - $\text{first-terminal-pos}$ — это самый левый конец *хотя бы какого-то* совпадения в тексте. Пусть это совпадение начинается в $i_{\text{first}}$ и заканчивается в $\text{first-terminal-pos}$.
   - Так как $i_{\text{first}}$ — это старт валидного совпадения, а $i_{LL}$ по определению является *самым левым* стартом среди всех возможных совпадений, то $i_{LL} \le i_{\text{first}}$.
   - Поскольку $i_{\text{first}} \le \text{first-terminal-pos}$, получаем строгое неравенство: $i_{LL} \le \text{first-terminal-pos}$.

2. **Инвариант $j_{LL} \le \text{potential-rightest-end}$**
   - Неравенство $i_{LL} \le \text{first-terminal-pos}$ означает, что к моменту достижения $\text{first-terminal-pos}$ во время прямого непривязанного прохода ветка для $i_{LL}$ **уже была создана** и находилась в каноническом множестве состояний ДКА.
   - Когда на $\text{first-terminal-pos}$ удаляется `unanchored-start-state` и запускается прямой привязанный жадный проход, ветка для $i_{LL}$ **не уничтожается** — она продолжает вычисляться вправо.
   - Следовательно, эта ветка гарантированно дойдёт до своего терминального состояния $j_{LL}$. А значит, $\text{potential-rightest-end}$ будет либо равен $j_{LL}$, либо уйдет правее.

3. **Гарантия охвата всех концов $j$ в обратном проходе**
   - Из пунктов 1 и 2 следует, что конец абсолютно любого валидного совпадения $j$ (включая $j_{LL}$) строго принадлежит отрезку $[\text{first-terminal-pos}, \text{potential-rightest-end}]$.
   - Запуская **обратный непривязанный жадный проход** на отрезке от $\text{potential-rightest-end}$ до $\text{first-terminal-pos}$, мы засеиваем реверсивный ДКА начальными состояниями для всех $j \in [\text{first-terminal-pos}, \text{potential-rightest-end}]$. В частности, на шаге $j = j_{LL}$ гарантированно создается реверсивная ветка для $j_{LL}$.

4. **Нахождение $\text{leftmost-start}$ в обратном привязанном проходе**
   - На позиции $\text{first-terminal-pos}$ удаляется реверсивный `unanchored-start-state` и запускается **обратный привязанный жадный проход** влево до $\text{left-bound-pos}$.
   - Попадание в терминальное состояние в реверсивном ДКА означает нахождение позиции $i$ (начала совпадения).
   - Так как проход жадный и идёт справа налево (к уменьшению позиций), последнее (самое левое) найденное терминальное состояние и будет являться минимальным $i$ — то есть $\text{leftmost-start} = i_{LL}$.

5. **Финальный прямой привязанный проход**
   - Зная точный $\text{leftmost-start}$, запускается прямой привязанный проход от $\text{leftmost-start}$ вправо, который находит точный $j_{LL}$ для этого конкретного $i_{LL}$.

Вся цепочка проходов полностью сохраняет свойства совпадения Leftmost-Longest/Shortest без использования тегов в ДКА.
