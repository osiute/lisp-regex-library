# Модуль engine
Конечный модуль, содержащий экспортируемые функции библиотеки.
## Терминология
- **Прямой проход** — посимвольная обработка строки `text` на заданном диапазоне [`left-bound`, `right-bound`] **слева направо** в поисках индекса `text-idx` такого символа, после прочтения которого **прямой ДКА** перешёл в терминальное состояние. В качестве результата прямого прохода возвращаются `text-idx` и `last-state-id` — id состояния, в котором оказался ДКА при завершении прохода.
- **Обратный проход** — посимвольная обработка строки `text` на заданном диапазоне [`left-bound`, `right-bound`] **справа налево** в поисках индекса `text-idx` такого символа, после прочтения которого **обратный ДКА** перешёл в терминальное состояние. В качестве результата прямого прохода возвращаются `text-idx` и `last-state-id` — id состояния, в котором оказался ДКА при завершении прохода.
- **Жадный проход** — проход, цель которого — поиск наиболее позднего индекса относительно стартовой позиции прохода. Для прямого прохода ищется самый правый индекс, на котором ДКА перешёл в терминальное состояние; для обратного — самый левый. Практически это означает: обработка строки до тех пор, пока ДКА не окажется в мёртвом состоянии или будет достигнут конец строки.
- **Ленивый проход** — проход, цель которого — поиск наиболее раннего индекса относительно стартовой позиции прохода. Для прямого прохода ищется самый левый индекс, на котором ДКА перешёл в терминальное состояние; для обратного — самый правый. Практически это означает: обработка строки до тех пор, пока ДКА не перейдёт в терминальное состояние (либо окажется в мёртвом состоянии, будет достигнут конец строки).
- **Вычисление ветки** — поиск лишь относительно заданного индекса $i$ такого индекса $j$, что ДКА переходит в терминальное состояние при обработке строки. На практике это означает: проверить, что для строки `text` существует подстрока, которая начинается в $i$ и соответствует паттерну регулярного выражения, а потом определить конец $j$ этой подстроки. Ещё проще: определение **вхождения** (подстроки, соответствующей паттерну регулярного выражения) **($i$ . $j$)**, где $j$ заранее неизвестен. Для обратного прохода определяется неизвестный $i$ относительно заранее известного $j$.
- **Привязанный проход** — проход, при старте которого ДКА не находится в непривязанном состоянии (каноническое множество состояний НКА не содержит `unanchored-start-state`). На практике это означает: во время прохода при переходе на каждый индекс `k` не добавлять новые ветки для вычисления, лишь продолжать вычислять уже добавленные.
- **Непривязанный проход** — проход, при старте которого ДКА находится в таком состоянии, которое содержит в своём каноническом множестве состояний НКА `unanchored-start-state`. Говоря проще, ДКА находится в непривязанном состоянии. На практике это означает: во время прохода для каждого текущего индекса `k` не только вычислять уже начатые ветки, но и добавлять на вычисление новую ветку (искать конец вхождения, в котором `k` — его начало). Аналог добавляения `.*` в начало выражения.

## Описание функционала и алгоритмов основных функций
- **`regex-match-p`** — проверяет строку на соотвтествие регулярному выражению. Использует прямой *привязанный жадный* проход на диапазоне [`left-bound`, `right-bound`];
- **`regex-search-p`** — проверяет строку на наличие **вхождений** (подстрок, соответствующих регулярному выражению). Использует прямой *непривязанный ленивый* проход на дипазоне [`left-bound`, `right-bound`];
- **`regex-find-first-match-bounds`** — вычисляет индексы первого по семантике **Leftmost** вхождения, имеет два режима: **longest**, **shortest**. Используются следующие проходы для определения границ:
  1. Прямой *непривязанный ленивый* проход на диапазоне [`left-bound`, `right-bound`] — *добавляем ветки для каждого `k`, до которого успели добраться*. Полученный индекс сохраняется как `first-terminal-k`, id состояния — `last-state-id`. Фактически определяет границу, где может находиться индекс `leftmost-k` для дальнешего поиска, а также добавялет ветки для всех потенциальных `leftmost-k`. Реально проходимый диапазон — [`left-bound`, `first-terminal-k`]. Если проход не попал в терминальное состояние, сразу возвращает `nil` — вхождения нет.
  2. Прямой *привязанный жадный* проход на диапазоне [`first-terminal-k` + 1, `right-bound`] с указанием стартового состояния как ранее сохранённого `last-state-id` с удалённым `unanchored-start-state` — *больше не добавляем новые ветки*. Полученный индекс сохраняется как `potential-rightest-end`. Фактически определяет границу, где может находиться потенциальный конец искомого вхождения.
  3. Обратный *непривязанный* жадный проход на диапазоне [`first-terminal-k`, `pontential-rightest-end`] (справа налево) без указания стартового состояния — *добавляем ветки для каждого потенциального конца*. Сохраняется только id состояния `last-state-id`. Фактически для всех потенциальных концов Leftmost-вхождения создаёт ветки для поиска начала.
  4. Обратный *привязанный* жадный проход на диапазоне [`left-bound`, `first-terminal-k` - 1] (справа налево) c указанием стартового состояния как ранее сохранённого `last-state-id` с удалённым `unanchored-start-state` — *больше не добавляем новые ветки*. Полученный индекс сохраняется как `leftmost-k`. Фактически определено начало вхождения.
  5. В зависимости от режима, на диапазоне [`leftmost-k`, `potential-rightest-end`] запускается *прямой привязанный проход*, опередяющий конец вхождения:
    - **longest** — *жадный*;
    - **shortest** — *ленивый*.
- **make-regex-match-bounds-iterator** — создаёт генератор, основанный на вычислении первого вхождения для заданного диапазона. Возвращает удобный итератор по нему.
 - **regex-split** и **regex-replace-all** используют итератор всех вхождений.

### Математическое доказательство корректности алгоритма поиска первого вхождения

Обозначим искомое **leftmost-longest** совпадение как пару индексов $(i_{LL}, j_{LL})$.

1. **Инвариант $i_{LL} \le$ `first-terminal-k`**
* `first-terminal-k` — это самый левый конец *хотя бы какого-то* совпадения в тексте. Пусть это совпадение начинается в $i_{first}$ и заканчивается в `first-terminal-k`.
* Так как $i_{first}$ — это старт валидного совпадения, а $i_{LL}$ по определению является *самым левым* стартом среди всех возможных совпадений в тексте, то $i_{LL} \le i_{first}$.
* Покольку $i_{first} \le$ `first-terminal-k`, получаем строгое неравенство: $i_{LL} \le$ `first-terminal-k`.
2. **Инвариант $j_{LL} \le$ `potential-rightest-end`**
* Положение $i_{LL} \le$ `first-terminal-k` означает, что к моменту достижения `first-terminal-k` во время прямого непривязанного прохода ветка для $i_{LL}$ **уже была создана** и находилась в каноническом множестве состояний ДКА.
* Когда на `first-terminal-k` удаляется `unanchored-start-state` и запускается прямой привязанный жадный проход, ветка для $i_{LL}$ **не уничтожается** — она продолжает вычисляться вправо.
* Следовательно, эта ветка гарантированно дойдёт до своего терминального состояния $j_{LL}$. А значит, `potential-rightest-end` будет либо равен $j_{LL}$, либо уйдет ещё правее (если другие зародившиеся до `first-terminal-k` ветки протянутся дальше).
3. **Гарантия охвата всех концов $j$ в обратном проходе**
* Из пунктов 1 и 2 следует, что конец абсолютно любого валидного совпадения $j$ (включая $j_{LL}$) строго принадлежит отрезку [`first-terminal-k`, `potential-rightest-end`].
* Запуская **обратный непривязанный жадный проход** на отрезке от `potential-rightest-end` до `first-terminal-k`, мы засеиваем реверсивный ДКА начальными состояниями для всех $j \in$ [`first-terminal-k`, `potential-rightest-end`]. В частности, на шаге $j = j_{LL}$ гарантированно создается реверсивная ветка для $j_{LL}$.
4. **Нахождение $i_{LL}$ в обратном привязанном проходе**
* На индексе `first-terminal-k` - 1 удаляется реверсивный `unanchored-start-state` и запускается **обратный привязанный жадный проход** влево до `left-bound`.
* Попадание в терминальное состояние в реверсивном ДКА означает нахождение позиции $i$ (начала совпадения).
* Так как проход жадный и идёт справа налево (к уменьшению индексов), последнее (самое левое) найденное терминальное состояние и будет являться минимальным $i$ — то есть $i_{LL}$.
5. **Финальный прямой привязанный проход**
* Зная точный $i_{LL}$, запускается прямой привязанный жадный проход от $i_{LL}$ вправо, который находит максимальный $j$ для этого конкретного $i_{LL}$ — то есть $j_{LL}$.
Вся цепочка проходов полностью сохраняет свойства совпадения Leftmost-Longest без использования тегов в ДКА.
