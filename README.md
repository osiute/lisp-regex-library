# REGEX-LIBRARY

**REGEX-LIBRARY** — это библиотека для работы с регулярными выражениями на языке Common Lisp (SBCL), построенная на базе алгоритма ленивой детерминизации (Lazy DFA). Проект разработан в рамках учебной курсовой работы по дисциплине «Архитектура и проектирование программных систем».

Основная цель библиотеки — обеспечение гарантированной линейной временной сложности поиска $O(N)$ от длины входной строки для всего спектра кодовых точек Unicode (`U+0000`–`U+10FFFF`).

---

## Архитектурные особенности

* **Ленивый ДКА (Lazy DFA):** Детерминированный конечный автомат не строится полностью заранее, а генерирует состояния и переходы по мере сканирования текста с сохранением их в динамическом кэше.


* **Гарантированное $O(N)$ и защита от ReDoS:** В архитектуре полностью отсутствуют алгоритмы поиска с возвратом (*backtracking*). Это исключает экспоненциальное возрастание сложности при проверке патологических шаблонов.


* **Рекурсивный спуск:** Синтаксический разбор регулярного выражения в абстрактное синтаксическое дерево (AST) осуществляется методом рекурсивного спуска.


* **Статические классы эквивалентности Unicode:** На этапе компиляции выражения входной алфавит Unicode разбивается на дизъюнктные интервалы эквивалентных символов, поиск по которым в процессе исполнения выполняется через бинарный поиск.


* **Автомат Томпсона (Forward & Reverse NFA):** Компиляция AST производит прямой и обратный недетерминированные автоматы. При реверсировании НКА непривязанное начальное состояние не разворачивает свои рёбра, а перенаправляется в новое привязанное начальное состояние (терминальное в прямом автомате).


* **Двунаправленный поиск:** Для точной поддержки семантики *Leftmost (Longest / Shortest)* используется двупроходный поиск на базе прямого и обратного ДКА.



---

## Поддерживаемый синтаксис и ограничения

### Поддерживаемые элементы:

* **Алгебраические операции:** Конкатенация, альтернатива (`|`), замыкание Клини (`*`).


* **Квантификаторы:** `+`, `?`, `*` точные повторения (`{n}`), диапазоны (`{m,n}`, `{m,}`).


* **Символьные классы:** Диапазоны (`[a-z]`, `[0-9]`), инверсия (`[^a-z]`), встроенные метасимволы (`\d`, `\w`, `\s`, `.`, `\D` и т.д.) и Unicode escape-последовательности (`\uXXXX`, `u{X+}`).


* **Якоря и границы:** Начало строки (`^`, `\A`), конец строки (`$`, `\z`, `\Z`), границы слов (`\b`, `\B`).



### Функциональные ограничения:

Для сохранения строго линейной сложности $O(N)$ в библиотеке **намеренно исключены**:

* Группы захвата (Capturing Groups);


* Обратные ссылки (Backreferences);


* Просмотры назад и вперёд (Lookarounds).

## Сравнение производительности и поиск с возвратом

В классических движках регулярных выражений, использующих алгоритмы **поиска с возвратом** (*backtracking*), отдельные паттерны на неподходящих входных данных вызывают катастрофический рост вычислительной сложности до $O(2^N)$.

Пример патологического выражения: `^(a+)+$` на строке `"aaaaaaaaaaaaaaaaaaaaaaaaaaaa!"`.

* Алгоритмы с **поиском с возвратом** застывают в экспоненциальном цикле повторного обхода дерева состояний.
* **REGEX-LIBRARY** благодаря детерминированному автомату обрабатывает данный паттерн за строго линейное время $O(N)$.



> **Текущий статус оптимизации:**
> Библиотека является учебным проектом и на данном этапе уступает продакшн-решениям (таким как `CL-PPCRE` или `RE2`) в среднем в 10 раз по сырой скорости на простых текстах из-за отсутствия низкоуровневых оптимизаций работы с памятью и выделениями компилятора. Однако гарантированная линейная сложность поиска вхождения сохраняется всегда. Проект содержит множество точек для будущих оптимизаций.

## Установка и подключение

Пока библиотека не опубликована в реестре Quicklisp, её подключение выполняется локально через ASDF.

### Вариант 1: Клонирование в директорию Common Lisp

Скопируйте репозиторий в каталог, который автоматически сканируется ASDF (например, `~/common-lisp/` или `~/.local/share/common-lisp/source/`):

```bash
cd ~/common-lisp/
git clone https://github.com/osiute/lisp-regex-library.git

```

После этого в REPL SBCL систему можно загрузить стандартной командой:

```lisp
(asdf:load-system :regex-library)

```

### Вариант 2: Загрузка через локальный `load.lisp`

Для удобной разработки и тестирования в репозитории предусмотрен скрипт `load.lisp`. Запуск REPL с автоматической загрузкой системы и тестов:

```bash
rlwrap sbcl --load "load.lisp"

```

В интерактивной сессии можно переключиться на пакет и вывести справочную информацию:

```lisp
(in-package :regex-library) ; или использовать псевдоним (in-package :re)
(print-help)

```

Функция `(print-help)` выведет список всех доступных тестов и вспомогательных команд REPL.

## Быстрый старт (API)

Пакет зарегистрирован под именем `:regex-library` и содержит сокращенные псевдонимы `:regex` и `:re`.

```lisp
(in-package :cl-user)
(use-package :re)

;; 1. Проверка наличия совпадения
(contains-p "\\d+" "Номер заказа: 4829") 
;; => T

;; 2. Поиск границ первого совпадения (возвращает точечную пару или NIL)
(first-match-span "[а-я]+" "abc 123 текст test") 
;; => (8 . 13)

;; 3. Поиск всех совпадений в строке
(all-match-spans "\\b\\w+\\b" "Быстрый старт библиотеки") 
;; => ((0 . 7) (8 . 13) (14 . 24))

;; 4. Замена всех найденных фрагментов
(replace-all "\\s+" "Много   лишних   пробелов" " ") 
;; => "Много лишних пробелов"

;; 5. Разделение строки по разделителю
(split "," "яблоко,груша,банан,слива") 
;; => ("яблоко" "груша" "банан" "слива")

;; 6. Компиляция шаблона для повторного использования
(let ((compiled-re (compile-regex "\\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}\\b" :unicode)))
  (matches-p compiled-re "user@example.com"))
;; => T

```

## Запуск тестов

Библиотека покрыта набором модульных и интеграционных тестов.

### Выполнение через ASDF:

```lisp
(asdf:test-system :regex-library)

```

### Выполнение из REPL (при загруженном `load.lisp`):

```lisp
(in-package :re)

;; Запустить всё тестовое покрытие
(run-all-tests)

;; Запустить отдельные модули
(run-first-match-span-tests)
(run-ppcre-pathological-suite) ; Тест на ReDoS / катастрофический возврат

```
